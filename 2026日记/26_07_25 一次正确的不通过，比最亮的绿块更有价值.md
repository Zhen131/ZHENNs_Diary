# 一次正确的不通过，比最亮的绿块更有价值

今天 GitHub 上的绿块可能不算特别亮。我记得自己 contribution 最多的一天，好像做了三十多个；今天从数字上看，肯定不是最多的一天。

但我还是觉得今天很重要。

最近家里面、亲戚朋友之间有很多烦心事，也有很多麻烦要处理。我的时间一直被切碎，真正能安静坐下来做高强度开发的机会并不多。所以今天能把第十周从文档审查一路推进到开发和独立测试，本身就很难得。

更重要的是，我今天不是只让 AI 写了一堆代码，而是第一次比较完整地组织了一套软件工程流程。

## 上午先把模糊的东西说清楚

今天一开始，我没有急着写代码，而是先重新审查第十周的 01A。

以前我很容易在需求还没有说清楚的时候，就把任务交给 AI。AI 确实会往下写，但我自己其实不知道它会怎么理解，整个开发过程很像一个黑盒。今天我第一次强烈感受到，计划模式可以把我脑子里那些模糊的目标变清楚，也可以把容易滑动的边界固定下来。

在几轮讨论之后，第十周的关键事实终于定住了：原来的两张图改成三张图，图表库使用 Apache ECharts；三张图分别是持仓市值饼图、总市值与持仓成本的阶梯曲线，以及最近 365 天的交易热力图。

有些看起来很小的地方，其实非常影响最后会不会做错。比如热力图的零档就是完全没有交易、没有颜色；有交易以后再分四档，即使数据是 1、1、1、30，三个 1 也必须落在最低亮度，30 落在最高亮度。

行情和估值的边界也重新说清楚了。Binance 使用不需要 API Key 的公开行情接口；行情失败时不能清空旧价格，不能写入 0，更不能影响本地账本继续使用。持仓表、饼图和曲线必须共用同一套选价规则。没有价格就诚实显示缺失，不能拿交易价、成本或未来价格伪造市值。

这些事实确认以后，我把它们整理成 01B，再结合 01A 和 01B 生成真正供执行使用的 01C。

01C 已经很长了，我还是继续审查。我把 Git 规则、Gate 依赖、数据合同、执行顺序和禁止事项又补了一遍：开发要使用独立分支，关键节点要有中文提交，不能擅自推送和合并；后面的 Gate 不能反过来成为前面 Gate 的前置条件；执行时以 01C 为准，01B 和 01A 只负责补充，不能又退回旧 Checklist。

这一步没有直接长出任何页面，但它决定了后面的 AI 会不会跑偏。

我觉得计划模式不只是一个写计划的工具。它其实也是一种新的[[../2024日记/学习方法]]：我在回答它的问题、审查它的表述时，也在逼自己搞清楚这个系统到底要解决什么，哪些东西可以妥协，哪些东西绝对不能伪造。

## 我开始牵着 AI 走

计划确定以后，我把 01C 交给另一个聊天，用目标模式持续执行。

这里的分工开始变得很清楚：计划模式负责澄清目标和边界，目标模式负责让任务持续推进，开发 AI 负责实现，而最后的判断仍然在我手里。

我没有亲手敲下每一行代码，但需求、边界、先后顺序和验收标准，是我一轮一轮决定的。今天我第一次很明显地感觉到，我不是把项目扔给 AI，也不是被 AI 牵着鼻子走，而是在建立自己的[[AI协作]]方式。

第十周最后从文档里的三张图，变成了真正运行在[[账本系统]]源码里的功能。开发过程处理了日期和旧未来事实的兼容边界，接入了 Binance 公开行情和统一选价服务，建立了三张图共用的持仓重放与图表派生服务，也完成了 ECharts 的 React 生命周期适配、三张图、日期筛选以及行情和备份恢复链路的安全回归。

移动端图表把整页撑宽的问题也被修掉了。

开发侧最后有 41 个测试文件、362 项测试通过，lint、production build 和 diff-check 也都通过。真实 Binance 刷新成功拿到了三个资产的行情，390 像素和 1280 像素页面都检查过，控制台没有 warning 和 error。

如果只看到这里，确实很容易觉得第十周已经完成了。

## 我没有直接相信开发 AI 的自测

开发 AI 完成以后，给了我一份 02A 验收记录。

但开发者自己写代码、自己测试，容易只验证自己已经想到的情况。所以我又建立了 02B 独立测试标准，准备交给另一个 AI，用测试人员的身份重新检查。

连测试计划本身，我也没有直接相信。

我又审查了应该在当前目录还是新 Worktree 执行、临时测试接线允许增加什么、abort 之后仍然返回的旧请求如何证明不能污染新账本、部分成功应该产生几次 mutation 和 save、未来事实测试与 production V2 加密证据如何分开，以及 `npm audit` 返回非 0 时到底是发现漏洞还是命令执行失败。

这些问题补清楚以后，我才把 02B 交给新的独立测试 AI。

最后独立测试给出的结果不是我希望看到的“通过”，而是“不通过”。

大部分能力其实都经受住了测试：自动化基线、Binance 各类失败和部分成功的降级、旧请求不能覆盖新账本的竞态保护、三张图、真实行情、备份恢复、响应式页面，以及未来事实隔离都通过了。

但它还是找出了两个不能忽略的问题。

第一，正式页面虽然能识别错误的未来交易和未来价格，也能一次性把它们全部删除，却不能逐条删除。这意味着用户没有一个足够细的纠错入口，必测交互合同没有真正完成。

第二，`next@14.2.35` 存在一个对当前 `next start` 部署面可达的 WebSocket SSRF 高危漏洞，被判定为 P1。业务功能做完了，也不能带着这种问题进入合并审查。

另外，production 原始 IndexedDB V2 envelope 的部分证据，因为当前浏览器能力限制没有完全取到。这不代表加密一定有问题，但说明证据链还没有闭合。

所以今天最后的决定是：第十周功能开发完成，但独立验收不通过。源码继续留在 `zhennn/week10-charts-binance` 分支，不合并，下一步先制定独立修复计划。

文档仓库和源码仓库今天产生了很多有明确目的的提交，最后也都保持干净并同步到了远端。但我现在越来越觉得，commit 数量和绿块亮度只是[[反馈系统]]的一部分，真正重要的是这些流程有没有改变最后的决定。

今天它们确实改变了结果。原本可能被直接合并的代码，因为独立测试，被安全地留在了功能分支上。

## 计划模式让我从黑盒里走出来一点

回头看[[26_07_12 送爸爸去高铁站后，我不想再做完美主义者|7 月 12 日]]，我当时的想法还是：账本先让它黑盒，先借助 AI 把它推出来，再慢慢理解。

这个判断在当时没有错。可今天我又往前走了一步。

我不一定能立刻看懂每一行代码，但我可以把需求、数据来源、失败边界、测试证据和合并条件说清楚。计划模式把原本完全黑箱的开发，变成了一组可以提问、审查、执行和否决的东西。

它不只提高了我的工作效率，也让我更容易学习。很多原本说不清的东西，在计划模式连续追问之后，我反而能输出很多观点，也能看见自己真正想要什么。

这是一种很具体的[[主体性]]：AI 可以写代码、写计划、执行测试，但我要决定问题是什么，什么结果可信，以及什么时候必须说“不通过”。

今天我好像第一次比较完整地体验了产品经理、架构师、项目负责人、测试负责人和安全负责人这些不同角色。我当然还远远谈不上专业，但我已经不再只是对 AI 说一句“帮我写代码”了。

## 早上做最难的事，晚上做轻一点的事

今天还有一个很重要的发现：我越来越喜欢在早上刚睡醒、脑子最清楚的时候，做一天里最难的工作。

早上进入计划模式时，我的想法很多，能连续输出观点，也能抓住边界。那时候是我在布置任务、审查 AI、牵着 AI 往前走。

可到了下午和晚上，哪怕我并不困，脑子也已经没有办法长时间高强度集中。一天积累下来的疲惫会让我失去判断力。有时我甚至不知道该怎么继续布置任务，慢慢就变成了 AI 牵着我走。

这说明我的[[注意力管理]]不能只管手机和短视频，也要管理一天里不同时间段的精力。

以后早上最清醒的时间，应该尽量留给全栈之路和真正困难的项目开发。晚上则可以维护编程宝典、历史金融图谱和日记，做一些轻量的阅读、整理和文本撰写。

我现在有很多仓库，不需要每一个时间段都硬做最难的事情。把不同难度的工作放进合适的精力窗口，也是一种效率。

## Pro 会员和我的“蹬自行车”

最近我还开了 ChatGPT Pro，差不多一个月一百美元，也就是七八百块人民币。

价格确实不低，但我觉得相当划算。

我把高强度使用 GPT 叫作“蹬自行车”。以前 Plus 一周的用量，我差不多一天就能蹬完。换成现在这个 5 倍 Pro 以后，一天大约只会用掉一周额度的 20%，这个量对我来说舒服多了。

我的下一个目标，甚至是争取有一天能在一天里蹬完一周的 5 倍 Pro 用量。真到那个程度，我就会去开 20 倍 Pro。

听起来可能有点夸张，但这对我来说已经接近刚需。无论是维护全栈之路、编程宝典、历史金融图谱和日记，还是做计划、开发、测试和学习，我现在都离不开它。

这笔钱买的不只是更多对话次数，而是我每天能调用的一套思考、开发和整理能力。只要我真的会用，它就值得。

## 今天最重要的不是绿块

今天 GitHub 上的绿块不是最亮的。

但我第一次很完整地走过了：确定需求、审查歧义、制定计划、交给 AI 开发、检查开发结果、建立独立测试标准、再交给另一个 AI 测试，最后根据证据决定能不能合并。

如果只看开发侧的 362 项测试，今天下午我就可以宣布第十周完成了。可因为晚上多了一层独立测试，我真的找出了一个交互缺口和一个 production 高危依赖问题。

所以今天增加的计划、审查和测试不是多余流程。

有时候，一次正确的“不通过”，比几十个看起来漂亮的 contribution 更有价值。
